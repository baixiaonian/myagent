# 上下文设置、使用与维护

## 使用

模型设置中填写服务商公布的上下文窗口和期望输出预留；200000/4096 是产品默认，不能视为模型识别结果。系统自动扣除安全余量，输入区显示估算占用。接近容量时会使用同一连接整理历史，产生额外模型请求，次数和已知 usage 在面板中展示。

点击上下文面板查看摘要和来源；来源可以分页查看。模型也能主动查询本会话原文，大工具结果通过结果引用继续读取。摘要不会删除聊天正文和已经保存的结果。

若显示“等待整理上下文”，可重试整理，或先在模型设置修改容量，再点“应用最新容量并继续”。这不会切换进行中 Run 的模型。规则/工具 Schema/当前问题自身过大时，应增加真实可用容量、缩短项目规则或将部分 MCP 改为按需提供；仅反复重试摘要不能解决。

项目规则只读取工作区根 AGENTS.md，在 Run 开始时冻结。缺失允许继续，越界链接、读取失败、超过 64 KiB 或内容变化会明确报错。嵌套规则尚未实现；自动长期记忆见 [记忆维护](memory.md)。

## 兼容配置

200k 表示 200000 token；默认输出预留 4096、安全余量 30000，可用输入预算 165904，整理阈值 132723、整理目标 99542（均为估算 token）。新连接或缺少容量字段的旧配置使用这个默认；已经保存的容量以及在途 Run 快照保持原值。需要更新现有配置时，在模型设置中保存新容量，下一 Run 生效；暂停中的 Run 可选择“应用最新容量并继续”。

默认不再使用 32000 字符硬裁剪。显式 MYAGENT_CONTEXT_CHARACTERS 仍是附加上限，不是 token 数；需要大窗口时也应检查是否设置了这个旧变量。MYAGENT_HISTORY_TURNS 控制近期原文偏好，较早记录纳入摘要而非被静默删除。单条结果投影仍最多 8000 字符，按实际预算可缩小。

单次结果捕获最多 20 MiB、每 Run 最多 100 MiB；采集不完整和仅预览截断分别展示。系统不知道丢失总量时不填造 0。停止、超时和上下文整理不代表已发生的文件/远端副作用回滚。

## 升级、备份与验证

停旧进程，备份完整数据目录和独立工作区，再安装并运行新版本。v6 自动迁移；回退需要恢复 v5 备份，旧程序不能打开 v6 数据库。摘要和来源在 state.db，工具大结果在 results/；备份只复制数据库而不复制结果文件会破坏引用。删除会话清理其上下文派生资料，但保留项目文件及既有未知副作用隔离记录。

- `pnpm test:context`：容量、摘要、分块、协议估算、取消和恢复专项。
- `pnpm verify`：工程全量检查。
- `pnpm test:e2e`：独立浏览器验收，包含容量、摘要、来源分页和刷新。
- `pnpm test:docker`：独立容器升级、摘要及结果持久化。
- `pnpm test:context:live`：已授权后使用当前连接，在独立实例分别验证两种协议的真实摘要和历史查阅；会产生费用，不进入 CI，不修改原配置。

真实验收任务是查询上海/纽约当前时间并随后核对先前的项目代号；通过注入较低压缩阈值触发整理，不要求用户知道工具名称。假模型测试、真实模型和 Docker 证据分别记录，不互相替代。
