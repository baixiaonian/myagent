# 命令权限使用与维护

权限模式补充：本文中的命令规则、审批与沙箱保证适用于默认**标准权限**。用户可在输入框旁选择**完全访问**，新 Run 与成员免命令/资源审批并采用无沙箱工具进程；停止、超时、版本和未知结果校验仍保留。Hook 继续使用独立授权。详见 [执行模式 v13](../protocols/execution-mode-v13.md)。


从侧栏打开“命令权限”，无需先创建会话。用户级规则供所有项目使用；选择项目后可查看项目规则和检查命令。表单的“加入规则草稿”不会立即生效，需点击“保存命令规则”；JSON 编辑器操作同一份草稿。

默认 `pwd`、限定参数的 `ls`/`cat`/`head`/`tail`/`wc`/`grep`/`rg` 可以自动执行。`git status`、安装、删除、脚本和复杂 Shell 默认询问。添加 `["git", "status"]` 的 allow 可以放行该参数前缀；加入同前缀 prompt 或 deny 会收紧结果，项目 allow 不能覆盖用户限制。

“规则测试”只检查已保存配置，不执行命令，也不代表文件/网络授权已经通过。测试结果显示命中的规则来源；真实运行还会重新检查并进入沙箱。放行解释器意味着信任它及其子进程；交互程序获准启动后，后续输入不再逐次审批。

命令审批展示完整命令、目录、询问原因和额外资源，只有本次批准。想长期放行请通过设置添加规则；原有纯文件/MCP 资源审批仍支持本次/会话/工作区。

## 文件编辑与故障处理

- 用户规则默认 `~/.myagent/command-rules.json`，随数据根配置改变；项目规则为 `.myagent/command-rules.json`。完整格式见 [协议](../protocols/commands-v5.md)。
- 外部编辑后，页面会识别版本变化，保留现有草稿；“加载新版本”会替换页面草稿。非法 JSON 显示错误，先修复再保存，不会自动清空。
- 项目规则出现、改变或删除，需要核对新旧规则并确认当前版本。待确认或配置错误时，新命令返回明确错误。排版变化不新增权限，因此不重新确认。
- 保存冲突时重新加载当前文件并合并修改，不能盲目覆盖。已启动命令不随规则更改自动停止；使用运行的停止按钮取消。
- 升级前备份整个数据目录和工作区。v5 不能由旧程序直接打开；回退需要完整恢复升级前备份。删除聊天不会删除项目规则或文件。

开发验证使用 `pnpm verify`、`pnpm test:e2e`、`pnpm test:execution:native` 和 `pnpm test:docker`。原生专项只操作自身临时目录；工程模型替身不代表真实模型自主判断已验收。
