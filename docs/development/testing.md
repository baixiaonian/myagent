# 验证策略

当前业务模块为空，不为占位文件创建功能测试。现有 tests/architecture 用于检查工程边界工具本身，确保越层、深路径、跨包相对访问和循环能被拒绝。

未来验证按职责增加：

- unit：状态机、预算、上下文选择与权限的真实分支。
- contract：模型 / 工具 / 执行 / 存储适配器的共同语义。
- integration：崩溃恢复、取消、审批恢复、事件补读和未知副作用对账。
- e2e：用户任务输入到有版本产物的完整行为。
- evals：真实任务质量、可核对来源、成本和耗时。

FakeModel / FakeTool / FakeClock 的位置已预留，尚无实现。上游研究项目从所有产品检查中排除。

pnpm verify 串联格式、依赖边界、文档、类型、工程测试和构建。CI 配置相同命令。远程 CI 尚未执行；本地结果记录在 history，不能把配置存在视为远程已通过。
