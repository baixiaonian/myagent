# 安装、使用与维护

## 环境与启动

推荐 Node.js 24 LTS，pnpm 11.7.0。安装 `pnpm install --frozen-lockfile`；安装脚本仅允许 esbuild 和 better-sqlite3。若 SQLite 原生模块找不到适配当前 Node ABI 的预编译包，安装 Python 3 和本机 C++ 工具（macOS Command Line Tools；Linux make/g++）。切换 Node 主版本后重新安装或 `pnpm rebuild better-sqlite3`。

- `pnpm dev`：先构建内部包，然后同时启动 TypeScript 编译监听、Node 后端监听和 Vite，页面 <http://127.0.0.1:5173>，后端 3000。Ctrl+C 停止整组进程。后端模块重新编译会重启服务，正在生成的 Run 会中断，开发时属于预期行为。
- `pnpm build && pnpm start`：生产 Web 和 API 统一在 <http://127.0.0.1:3000>。
- `pnpm verify`：工程、类型、单元 / 集成测试和生产构建。
- `pnpm test:e2e`：先构建，再启动临时数据目录的测试服务与本地假模型，运行 Chromium。首次需要 `pnpm exec playwright install chromium`。

`MYAGENT_DATA_DIR` 覆盖默认 `~/.myagent/`；`PORT` 指定后端端口（开发代理自动同步），`MYAGENT_WEB_PORT` 指定 Vite 端口。例如 `PORT=3001 MYAGENT_WEB_PORT=5174 pnpm dev`。`.env.example` 仅示例，不自动读取。开发时使用 `MYAGENT_DATA_DIR=/absolute/path pnpm dev`。不要把 API 密钥写入 `.env`、启动参数或源码。

## 首次配置

在设置中选择 Responses 或 Chat Completions，并填写完整基础地址，如服务商提供的 `https://example.com/v1`，不追加 `/responses` 或 `/chat/completions`。新界面默认 Responses，升级已有连接仍按原来的 Chat Completions 工作。模型 ID 手动填写，大小写按服务商要求。填写密钥和可选系统提示词；点击测试连接验证所选协议的一次真实简短请求（可能产生费用，不进入历史），再保存。系统提示词最多 4000 字符。协议不支持时按服务商文档手动更换，不自动探测或切换。

读取设置只显示掩码。留空密钥保存其他设置会保留原密钥；输入新值会替换；垃圾桶按钮清除已保存密钥。正在生成的请求使用启动时快照，新设置从下一次生成生效。

## 使用行为

Enter 发送，Shift+Enter 换行，中文输入法确认候选时不会发送。生成中可继续写草稿；草稿只保存在当前页面内存，刷新会丢失未发送草稿。刷新、关闭页面不会取消后端回答。向上阅读暂停自动滚动，可点向下箭头回到底部。

首次问题取前 32 字符作为标题；可随时重命名。重新生成复用最后一个问题，使用当前连接，可能再次执行工具；成功后替换原答案和计划，失败保留原完整答案与计划并展示错误。原始版本及失败候选仍保存在数据库便于追溯；删除会话会级联删除所有版本、步骤及事件。

模型自行决定直接回答或调用工具。当前有文件、命令、MCP、真实时间查询与可选计划工具；工作区与授权入口见 [工具使用](tools.md)；只有模型更新计划后才出现计划卡片，清空列表会隐藏卡片。展开执行过程可查看模型中间文字、参数、状态和完整结果。计划只是模型的工作清单，程序不按计划调度，也不因全部勾选而自动结束。

输入最多 8000 字符。上下文窗口与输出预留在模型设置中配置，默认 200000/4096；按实际序列化输入估算并扣除安全余量。接近容量时摘要较早历史和已完成工具步骤，近期原文优先保留，当前问题不静默删除。失败/停止/被替换候选不会当作成功对话，但已发生副作用仍可查阅并接受隔离治理。估算不是精确 token；服务商明确拒绝窗口时暂停，等待调整或整理。完整说明见 [上下文维护](context.md)。

以下服务端启动变量可覆盖默认值，须为正整数；配置从下一次 Run 开始生效。不限制固定轮数、任务总时长或累计产出；上下文管理控制每次请求容量，单次调用仍有超时。

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| MYAGENT_MODEL_TIMEOUT_MS | 120000 | 每次模型请求时限 |
| MYAGENT_TOOL_TIMEOUT_MS | 30000 | 单个工具执行时限 |
| MYAGENT_COMMAND_TIMEOUT_MS | 600000 | 单个命令进程的默认时限；不是任务总时限 |
| MYAGENT_CONTEXT_CHARACTERS | 默认不启用 | 上下文字符预算（含工具与续接） |
| MYAGENT_HISTORY_TURNS | 3 | 近期原文保留偏好，非历史删除上限 |
| MYAGENT_TOOL_RESULT_CHARACTERS | 8000 | 工具结果回传模型的文本上限，截断明确标记 |

MYAGENT_RUN_TIMEOUT_MS / MYAGENT_OUTPUT_CHARACTERS 已停用，残留配置仅提示且忽略。旧检查点中的任务时限和累计配额也不再执行；已失败或已停止任务不会自动重跑。单命令 timeoutMs 可独立指定（当前工具参数上限 600000ms）；未指定时使用上述服务端默认值。

工具结果按采集容量保存在本地，采集不完整会明确标记。工具参数或可恢复执行失败会反馈给模型；模型错误、截断和单次请求超时终止当前 Run，上下文容量问题进入可恢复暂停。模型与工具都不由程序自动重试；模型收到工具错误后可自行选择修正再调用。

## Docker

`docker compose up -d --build` 构建并启动，打开本机 3000。`docker compose logs -f` 查看脱敏服务日志，`docker compose down` 停止但保留卷。命名卷会带 Compose 项目前缀；可用 `docker volume ls` 查看。容器内数据库目录 `/data`，容器使用普通 node 用户。Docker 中 `127.0.0.1` 指容器自身，连接宿主机模型通常使用 `host.docker.internal`（Linux 需自行配置宿主机网关）。

Compose 只映射 `127.0.0.1:3000:3000`。`MYAGENT_CONTAINER=1` 仅供容器内部绑定使用，不能作为公网部署开关；应用仍限制本机 Host 和 Origin。没有身份认证，不能通过反向代理开放给公网用户。

## 升级、备份和恢复

1. 停止本机服务或 `docker compose stop`，确认没有进程写入。
2. **完整复制数据目录 / 命名卷**到受限备份位置；包括 `state.db`、可能存在的 `state.db-wal`、`state.db-shm` 、`credentials.json`、`results/` 和 `execution/`。不要只复制正在运行的主数据库。备份含明文密钥，应与数据目录同等保护。
3. 更新源码，运行锁定依赖安装、`pnpm verify`、`pnpm build`；Docker 使用 `docker compose build`。
4. 启动新版本，检查健康接口与历史会话。迁移根据 SQLite `user_version` 在事务中自动执行；v1 对应 [初始迁移](../../migrations/0001_chat.sql)，v2 的 [Agent 迁移](../../migrations/0002_agent.sql) 新增步骤记录。v3 的 [执行迁移](../../migrations/0003_tools.sql) 增加工作区、调用、授权与检查点。旧聊天无步骤仍正常显示，旧连接不改变协议。新版数据库拒绝被旧版应用打开，降级需同时恢复匹配版本的完整备份。

恢复时先停止服务，替换整个目录 / 卷内容，恢复目录 0700、凭证和数据库 0600 权限，再启动。不要同时对同一目录运行两个服务。进程锁为数据目录内的 `server.lock`（锁目录），不会写入数据卷父目录。启动兼容检查旧版本的数据目录旁锁，升级需先停止旧实例。目录锁可在异常退出后约 10 秒失效；不要在活进程仍运行时手动删除锁。数据库升级或恢复前始终保留原备份。

## 删除与排障

- 删除会话：侧栏删除按钮确认，活动回答先取消；删除后不会被迟到结果恢复。
- 删除密钥：设置中的清除按钮；已开始的请求仍使用快照，必要时先停止生成。
- 删除全部数据：停止服务，再删除自己确认的数据目录；Docker 使用 `docker compose down -v` 会永久删除本项目卷。此操作不可撤销，必要时先备份。
- 接口 / 模型不存在：核对基础地址、模型 ID 和所选协议，尤其是否重复拼接 `/chat/completions` 或 `/responses`。
- 密钥无效：检查该密钥的模型访问权限；限流也可能是额度不足。
- 模型余额不足或计费受限：上游 HTTP 402 会明确显示该原因，到服务商处检查余额和计费状态后再重试；缩短对话不能解决余额不足。“费用未知/未计价”表示本地缺少价格或 usage，不代表服务商免费。系统不会自动重发失败的付费请求。
- 连接或超时：检查服务商网络、代理、接口是否支持所选协议的流式及函数调用；本实现不承诺所有兼容服务行为一致。
- 无法启动：检查端口占用、目录权限、SQLite 原生驱动和已有实例；不能读写磁盘时先修复磁盘问题，勿反复重试生成。
- 服务意外退出：重启后有检查点的 Run 等待核对后手动继续，旧 Run 标记 interrupted；保留最近已提交的部分（最多约 250ms 增量未落盘），不自动调用模型或重放工具。

Docker 构建的 APT 下载显式使用 IPv4、30 秒超时和 3 次重试，避免下载无进展时无限等待；不修改宿主机网络设置。

## 项目与 MCP（v4）

新对话直接选择本机目录，默认每对话独立工作目录；MCP 支持用户级和项目级文件/表单设置。详见 [使用说明](projects-mcp.md)。当前数据库升级至 v4，备份增加工作区独立卷；全部数据删除必须同时核对工作区产物。

上下文窗口、自动整理和 v6 升级/备份见 [上下文维护](context.md)。

当前数据格式为 v7，升级/备份需包含 `memories/` 与 SQLite；默认关闭长期记忆，侧栏单独开启。见 [记忆使用维护](memory.md)。

团队使用现有启动命令，无新增服务。成员数和模型并发通过 MYAGENT_TEAM_MAX_MEMBERS（8）、MYAGENT_TEAM_MODEL_CONCURRENCY（4）设置；见 [团队维护](teams.md)。

## 执行权限选择

输入框旁选择“完全访问”后发送任务，主 Agent 和成员可以自主执行文件、Shell、已启用 MCP 工具，不再等待命令或资源审批。选择会在本浏览器保留；初次使用默认标准权限。运行中模式锁定，要更换需停止并新发任务。

完全访问不使用 MyAgent OS 沙箱，能访问服务端系统用户可访问的文件（包括凭证文件）和网络；它不自动提升系统权限，也不扩大 Docker 挂载。Hook 配置授权、未知结果核对和副作用重新运行确认独立保留。细节见 [执行模式](../protocols/execution-mode-v13.md)。升级到 v13 前备份整个数据目录。
