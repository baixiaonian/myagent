# 使用和维护轻量团队

## 本地体验

配置有效模型后，在新对话选择一个临时项目，用自然语言说明目标即可；不需要手工运行协作工具。例如：

> 分析项目中的 sales.csv，计算各城市和总销售额，生成 analysis.md、review.md、summary.md。你可以让一位分析员和一位核对员协作，核对员直接向分析员确认口径。你自己也读取数据、检查两份结果并写最终总结。

首次体验可以明确让模型协作来验证产品能力；实际任务是否分工、创建哪些角色仍由模型决定。随后发送“让刚才的核对员再检查总额”，应复用已有成员。普通问答可以完全不创建成员。

聊天中的团队面板展示真实成员、状态、通信与过程。打开成员过程处理它的审批、上下文暂停或恢复；主 Agent 不能代批。可停止单个成员或关闭它释放名额；主输入框停止按钮会停止整个本轮团队。删除聊天保留项目产物。

## 配置与预算

| 环境变量 | 默认 | 含义 |
| --- | --- | --- |
| MYAGENT_TEAM_MAX_MEMBERS | 8 | 每团队未关闭成员上限 |
| MYAGENT_TEAM_MODEL_CONCURRENCY | 4 | 服务端全部模型请求在途上限，含摘要 |

主任务与成员没有任务总时限或累计字符配额；各自用上下文管理压缩历史，单次模型请求和工具执行仍有超时。等待成员不会额外占一个业务执行槽位；其他成员仍在工作时继续统计活动时间。增加并发不扩大执行权限。旧配置的 MYAGENT_RUN_TIMEOUT_MS / MYAGENT_OUTPUT_CHARACTERS 和旧检查点中的限制忽略，不需修改用户数据库。

## 验证命令

- `pnpm test:teams`：SQLite 协作、双协议 HTTP、消息/分支/恢复/审批和公平队列。
- `pnpm test:e2e`：包含团队面板、成员命令审批、刷新恢复与关闭成员。
- `pnpm test:execution:native`：macOS/Linux 沙箱、并行首次 Worker 复用和真实进程终止。
- `pnpm test:teams:live`：使用已授权本机连接，在临时实例分别验证两种协议；不修改持久设置。报告 `.cache/acceptance/teams-live.json`，不保存密钥。
- `pnpm test:docker`：v10→v11、隐藏内部会话、团队完成、重启和删除；沙箱可用性单独记录。

真实验收有模型费用，不能放入自动 CI。测试替身、真实模型、宿主沙箱和容器证据分开解释。当前最新结果见 [迭代记录](../history/2026-09-28-agent-teams.md)。

## 排查

waiting_agents 表示等待成员/消息，先查看是否有成员审批、上下文暂停或未知副作用；不应通过新建成员规避治理。重启后点击原任务恢复，系统不会自行重发付费请求。成员失败由主 Agent 决定如何交付；未知副作用先人工核对，不能直接假定没有执行。

升级前备份整个数据目录，项目产物另行备份。SQLite v11 不允许旧程序直接打开。团队数据库、结果文件和现有扩展快照一起恢复，不能只拷贝 team_records。当前没有跨机器 Agent 接入、worktree 自动合并或角色模板管理页。
