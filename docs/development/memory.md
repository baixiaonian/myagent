# 长期记忆使用与维护

侧栏点击“长期记忆”，不会创建空会话。首次默认关闭；勾选“启用长期记忆”并保存后，读取和空闲自动提炼生效。后台调用使用自己配置的模型，会产生额外费用；可单独关闭自动提炼或读取。

- **已有历史**：下方选择已经结束的会话，点击“开始整理”。首次开启不会自动回溯过去聊天。
- **自然语言更新**：“请记住我偏好先举例再解释”“将那条日志目录约定改成……”“请忘记刚才那条约定”。不明确时应先查阅和澄清。
- **人工管理**：新增、关键词搜索、按项目筛选、查看与编辑、查阅来源、忘记；最近一次可撤销的变更提供撤销入口。人工更正受到保护，后台不覆盖。
- **会话开关**：当前会话可单独禁止读取记忆或贡献新记忆，两个开关相互独立。
- **失败处理**：模型失败、服务重启、预算不足时任务保留进度，由用户明确继续。来源变化的旧候选不可直接继续，重新选择会话整理。额度是调用次数，token 用量缺失显示“未知”。

默认 30 分钟闲置、每分钟扫描、后台并发 1、每批 3 会话，每任务最多 8 请求/每天 UTC 32 请求，单请求 120 秒。页面“整理预算”可设置闲置时间、次数，API 可设置超时。前台运行优先；正在网络中的后台请求不会被反复取消和重试。

正文位于数据目录 `memories/MEMORY.md`（默认 `~/.myagent/memories/MEMORY.md`）。可用本机编辑器修改条目正文，保留格式与元数据；后台维护与页面刷新会识别变化。概览自动生成，请不要编辑它。遇非法文件或并发冲突先备份现场，修复正文到完整格式，再点“重试同步”；不能用空文件代替冲突解决。

停服后备份**整个数据目录**，包含 SQLite、凭证、记忆正文、提炼记录及结果文件；独立工作区另外备份。Docker 的 `/data` 数据卷已覆盖记忆，无需新增卷。恢复整份备份后启动，对账索引与正文；只复制 MEMORY.md 可以导入正文，但没有原数据库时不能保证旧来源可查。

删除会话会撤销自动贡献；独立新增的人工记忆保留。多来源条目若依据不足先隐藏，再按剩余来源重建。删除某条记忆会排除旧来源的自动提炼；新证据仍可形成新知识。删除不能撤回已发送给模型的内容或聊天里已有的引用。关闭记忆不会删除文件。

## 验证命令

- `pnpm test:memory`：本地临时文件/SQLite、双协议 HTTP 替身、取消/故障注入。
- `pnpm test:e2e`：浏览器管理和来源查阅；使用假模型，不代表服务商能力。
- `pnpm test:docker`：镜像启动、升级、数据卷/备份、双协议两阶段整理。
- `pnpm test:memory:live`：**需要有效配置与真实调用授权**。只读现有凭证，在临时实例分别验证两个协议；不修改用户配置或原记忆库。脚本每协议最多 28 请求，报告 `.cache/acceptance/memory-live.json` 只记录状态/计数。可用 `MYAGENT_SOURCE_DATA_DIR` 指定配置数据目录，不能把密钥放在参数里。

真实验收自然语言任务包括：A 会话说明已经核实的归档约定 → 手动整理 → B 会话查阅跨会话记忆及原出处 → 明确更正、遗忘 → 新会话不再注入旧条目。完整证据见 [迭代记录](../history/2026-09-26-long-term-memory.md)。
