# 一轮迭代怎样完成

1. 读 AGENTS → STATUS → 对应架构 / 协议 → 最近历史 → 目标模块局部规则。
2. 明确当前用户要求的可验证结果，选择一条纵向闭环；未授权的目标能力继续保留为计划。
3. 在已有职责目录实现，优先通过公开接口连接。新增依赖或包时同步工程清单和 ADR。
4. 运行适合变更的验证。交付前执行 pnpm verify；失败需修复或明确记录阻塞证据。
5. 同一轮更新 STATUS、相关知识页和 history；检查 AGENTS 是否仍准确，规则改变才修改。
6. 报告改了什么、怎么验证、还未实现什么。不要把工程构建通过表述成线上或产品验收。

## 文档更新对应表

| 变更 | 同步位置 |
| --- | --- |
| 新功能或行为变更 | STATUS、对应模块说明、history |
| 模块职责 / 依赖 | config/modules.json、architecture/modules、必要 ADR |
| 消息 / 命令 / 配置格式 | protocols、迁移说明、契约测试 |
| 开发命令 / 操作规则 | 根或局部 AGENTS、setup、history |
| 重要架构决策 | 新 ADR，更新有效架构页与索引 |

文档检查只验证结构完整性。代码、文档、状态的语义一致性需要在本轮审查，不能依赖自动时间戳或一句“已同步”。
