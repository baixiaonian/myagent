# 查看执行记录和费用

1. 左侧打开“执行记录与用量”，查看统计、模型请求、价格与保留设置，不会创建对话。
2. 开启“调试模式”后发送一个新任务。每次实际模型请求开始时读取开关，在途请求不受后来切换影响。
3. 聊天回答下方点击“执行追踪”，新标签打开独立链路页。左侧展开 Agent/步骤，中间瀑布图比较耗时，点击节点后在右侧查看属性、事件；模型节点的“模型输入输出”提供首包、首正文、usage、价格依据及原始材料。模型请求耗时包含网络，不等同于纯推理。
4. 原始视图支持续读、结构化格式化和下载。大文件按需读取；partial 表示文件本身采集不完整，页面分页不是数据丢失。关闭调试不会删除已有材料。
5. 代理接口或自定义模型在“模型价格”填写实际单价。相同模型名不会自动继承官方价；不知道价格时保留未知，不填写虚构数值。

聊天用量条与记录页显示服务商实际缓存命中率，口径为已知缓存请求的缓存输入 token / 输入 token 总和，不是逐请求百分比平均。缺失缓存字段或用量时显示未知请求数量；总 token 包含缓存读取，不代表全部按未命中单价收费。历史记录可以立即按已有 usage 展示，旧匿名汇总缺字段则保持未知。

离线复验：构建后运行 `pnpm test:cache:replay <已结束主 Run ID>`。默认只读本机数据，可用 `MYAGENT_SOURCE_DATA_DIR` 指定备份目录；需要已有完整 Chat Completions 调试输入。脚本使用当前上下文服务和内存库，禁止联网，不读取密钥，不输出历史正文，只比较请求前缀。实际命中率必须观察后续真实任务，不以此脚本的结构比例或推算费用当作账单。

真实任务例子：在测试项目准备 `expenses-a.txt` 和 `expenses-b.txt`，让 Agent“找一位成员核对 B，你自己核对 A，汇总费用”。时间轴应包含主/成员分支、工具过程和消息接收的 Link；费用请求数只按模型叶子调用累计。

## 服务端配置

| 环境变量 | 默认 |
| --- | --- |
| `MYAGENT_CAPTURE_FILE_BYTES` | 20971520，单份输入或输出 |
| `MYAGENT_CAPTURE_TOTAL_BYTES` | 1073741824，全库原始材料 |
| `MYAGENT_OTLP_ENABLED` | 未设置，即关闭 |
| `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` | 启用时默认 `http://127.0.0.1:4318/v1/traces` |
| `OTEL_EXPORTER_OTLP_HEADERS` | 可选 `name=value,name=value`；只供服务端导出，不传 Worker |

OTLP 仅导出元数据及事件。原始正文通过本机文件库独立管理；请把本地数据目录视为包含真实项目上下文的资料。模型调用错误可能出现在原始响应，调试正文不做替换。

数据仍在 `MYAGENT_DATA_DIR`（默认 `~/.myagent`），原始材料位于其 `observability/captures/`。备份应停止服务后复制整个数据目录，包含数据库与原始文件；恢复使用支持 v12 的程序。修改默认数据目录不能让模型文件工具访问原始库。

按保留期清理 Trace 不删聊天或费用账本。容量不足时回收最早已结束任务材料，保留 purged 状态。删除聊天清除对应明细和正文，但匿名历史费用仍存在；删除不能撤回此前已发给模型的内容。

## 验证命令与证据

- `pnpm test:observability`：真实本地 HTTP/官方 SDK、原始字节、费用/状态、文件故障、OTLP 接收器。
- `pnpm verify`、`pnpm test:e2e`、`pnpm test:execution:native`：工程、浏览器与本机隔离回归。
- `pnpm test:docker`：包含 v11→v12 数据卷、观测及材料重启验证。
- `pnpm test:observability:live`：已有授权连接的双协议临时实例验收；读取原配置但不修改，真实凭证仅在内存中使用。自然语言静态文件核对、成员、摘要及历史查阅；报告只保存计数/usage/状态/哈希，原始材料随后删除。

原始流收尾专项可运行 `MYAGENT_TEST_TRANSPORT_ONLY=1 pnpm test:observability:live`，每协议只发送一次无工具问题，独立保存 `observability-transport-live.json`，不覆盖完整场景报告。

完整报告位置 `.cache/acceptance/observability-live.json`；初次小窗口测试触及上限的失败与最终成功分别记录在本轮迭代中。费用是估算，真实调用成功不等于与服务商账单完成对账。


## 独立 Trace 页面

每条记录有本机地址 `/traces/<Trace ID>`。选中节点后地址带 `?span=<Span ID>`，可复制该链接、刷新或前进后退；此链接没有把数据发布到公网，其他机器不能据此访问本机记录。

工具栏支持节点/工具/模型/Agent 搜索、只看异常、全部展开/折叠；搜索临时展开匹配节点的祖先。详情面板可加宽，Esc 或右上角关闭，窄屏覆盖展示。同任务恢复段在同页归组，各段仍保留原身份；可沿因果 Link 查看来源。主 Agent 和成员是独立分支，点击创建/通信节点可跳到关联成员。

长链路先加载 200 个节点，点击“加载更多节点”继续；事件独立分页，搜索只针对当前已加载范围。直达较后节点会自动补读到其所在页，不把未读页当作空结果。选中模型节点即显示已经采集的输入与输出，不需切换详情 Tab；复制完整原文会补读全部已保存页面，采集缺损时仅能复制保存片段。材料“采集不完整”与“页面仅展示一部分”含义不同。未开启调试的旧请求不能补录。

生产本地更新先完成 `pnpm build`，在没有活动任务时重启 `pnpm start`，确保静态资产路由与新构建一致。开发时用 `pnpm dev` 的 Vite 页面即时预览。

成功 Step 默认折叠，展开可看上下文、模型和工具批次；异常或在途路径默认突出。手动展开/折叠优先于轮询。详情采用单页分区：业务证据、模型请求与原文、属性、事件和关联均可复制；上下文新增/变化/移出来源需要升级后的新请求才能采集，旧记录保持可读但不补造。
