# 项目与 MCP 设置

## 选择项目

侧栏点击项目行可展开/收起所属历史，对话按最近活动排序；项目右侧“＋”直接在该目录开始新对话，保留当前新对话草稿，发送前不创建空会话。“独立对话”收纳默认独立目录与遗留未绑定会话，不代表它们共享一个工作区。相同路径的旧目录身份只在界面归为一组，原绑定及权限不迁移。

新对话输入框下方点击“选择项目”，在轻量菜单中搜索最近项目或选择本地文件夹；按 Escape 返回输入区，点击外部关闭菜单。路径输入和目录浏览从“输入目录路径…”展开。选择、取消和错误均保留草稿，不创建空会话。macOS/Linux 桌面优先使用系统窗口；没有桌面时可输入路径或在页面浏览。这里的“本机”是后端所在机器，Docker 只能访问容器内已挂载的目录。

不选择目录也可以直接要求 Agent 创建文件、修改文件或运行命令。系统为每个新对话分配独立目录，默认根为 `~/MyAgent/Workspaces/`，可设置 `MYAGENT_WORKSPACE_ROOT`。点击已开始对话的项目入口可以查看实际路径和撤销额外授权。

开始后不更换当前会话目录，换项目请新建对话。删除聊天保留项目文件；清理默认目录前先核对实际产物，当前没有自动删除产物的机制。

目录被替换或磁盘重新挂载导致身份变化时，在新对话里重新选择目录即可登记当前身份；旧会话绑定与旧授权不自动转移。使用旧身份的会话仍会被执行校验阻止，需要新建对话选择当前目录。最近项目按规范路径显示最新一条。

## 添加 MCP

左侧“MCP 服务”不依赖当前会话。选择当前项目，按“全部 / 用户级 / 项目级”查看配置，然后点击“添加 MCP”。用户级默认供项目复用，项目级只对该目录生效。用户级与项目级同名时，项目级覆盖，包括禁用状态。

HTTP 填写 URL，可选 Bearer Token 或 OAuth。stdio 分开填写可执行命令和参数数组，不将整段 Shell 管道当作 command。需要下载或联网的程序在“额外访问范围”明确配置具体域名；不自动放宽沙箱和代理边界。

保存后自动连接；展开服务查看工具名称、描述和参数。需要 OAuth 时点击登录。连接失败显示状态和错误，点击“重新连接”重试连接；不会重放以前的工具调用。

添加或编辑服务时可选择“工具提供方式”：默认“按需加载”，由模型搜索并加载需要的工具；“直接提供”让该服务全部工具定义从首个模型请求起可见，同一项目可混用两种方式。直接提供不代表自动批准执行，工具较多时也会占用更多上下文；超出整体预算会提示 context_limit，不会悄悄只保留部分工具。

按需工具在同一会话后续提问时复用，刷新页面或后端重启后也会恢复仍有效的选择，不需要每次重新搜索。同一项目新建另一会话仍独立加载。配置/工具定义变更、禁用或不再允许该项目时，旧定义不再提供；断线期间也不可用。重新发现的新版本需要再次搜索。每次搜索最多 5 个，累计按需定义最多 16,000 字符，超限按最近选择顺序淘汰旧定义并在搜索结果中说明。旧版本检查点没有定义版本可核对，需要首次重新搜索。

复用省去搜索步骤，但仍会把有效定义放入每次模型请求，仍计入上下文；它不代替调用权限检查，也不自动执行或重放任何工具。删除会话会清理选择缓存，但保留项目文件。

## 编辑配置文件

用户级文件为数据目录下的 `mcp.json`，默认 `~/.myagent/mcp.json`；项目级为 `<项目>/.myagent/mcp.json`。设置页显示路径，可以用外部编辑器打开，也可以点击“编辑配置文件”使用页面 JSON 编辑器。

```json
{
  "mcpServers": {
    "local-server": {
      "command": "your-mcp-command",
      "args": ["--stdio"],
      "enabled": true,
      "toolExposure": "deferred"
    },
    "remote-server": {
      "transport": "http",
      "url": "https://example.com/mcp",
      "enabled": true,
      "toolExposure": "direct",
      "auth": "none"
    }
  }
}
```

以上是结构示例，没有预置服务。command/args 与 URL 要按你实际使用的服务填写；不自动导入其他应用的 MCP 配置。

`toolExposure` 省略时按 `deferred` 解释。项目级同名条目整体覆盖用户级；项目条目没填写此字段时回到按需默认值。外部修改项目文件中的提供方式也需要在设置页确认。

Token 和环境变量值在首次录入后转存本机凭证服务，配置中使用 `${secret:token}`、`${secret:env.NAME}` 等槽位。槽位绑定当前服务；复制到其他项目或更换服务地址时需重新填写，不会自动共享凭证。清除 Token 可在表单操作；环境变量删除对应键即可清除。

外部项目文件变化后显示“待确认”，可查看前后配置，确认该版本才连接。配置包含明文凭证时先确认转换。JSON 格式错误只显示安全位置；请在本地修复或在页面以此前有效文档重新编辑。遇到版本冲突先刷新，不覆盖其他编辑器的新修改。

## 验收命令与备份

- `pnpm verify`：类型、依赖、文档、单元/集成及构建。
- `pnpm test:e2e`：浏览器项目选择、默认目录、MCP 表单/JSON、聊天与审批回归。
- `pnpm test:projects:live`：需真实模型授权，独立临时环境验证默认/指定目录文件和命令任务；不会修改现有配置。
- `pnpm test:execution:native`：真实 OS 隔离与执行；系统文件夹窗口需另做本机交互验收，不能用注入选择器代替。
- `pnpm test:docker`：v1→v4、独立工作区卷、重启和备份恢复。

备份时停止服务，复制整个数据目录，并另行备份工作区和项目配置。Docker 的 `myagent-data` 与 `myagent-workspaces` 两个卷都需要保留；`docker compose down -v` 会删除这两类数据。目录选择不改变原生隔离要求；沙箱不可用时仍拒绝执行。
