# 可观测性 v1

业务历史继续负责真实执行与恢复；观测层记录关联、时间和调用账本。调试开关只决定是否另存 HTTP 正文，不改变 Agent 决策、工具权限或重试策略。

主链路：`ChatService / TeamService → 明确的 ObservationScope → ObservabilityService → SQLite / 原始文件库 / 可选 OTel 导出`。模型链路是 `全局公平队列 → 调用意图 → 模型适配器 → SDK fetch → 实际 HTTP`。

## 链路和计时

- 主 Run 建立 Trace，成员分支关联同一主 Trace。同进程内的审批、团队协调等待使用独立等待 Span，不因应用协程暂时退出而关闭主 Trace；上下文持久暂停、核对及重启恢复才形成新执行段，通过 Link 关联前段。
- Run、Step、模型、上下文准备/压缩、工具校验/权限/锁/槽位/派发、Hook 和进程是不同节点。进程句柄返回不结束 `process.lifecycle`；Worker 通过 IPC 回传真实终态及单调时钟测量值。
- request / inform / result 消息的入队、纳入模型请求、回复分别记录。接收节点 Link 指向发送节点；消息正文不在 Trace 中复制。
- `ObservationScope` 显式传递 Run、Step、成员、调用、attempt、进程、后台任务 ID。共享服务没有可变的当前异步 Span；Kernel 仅传递中立关联信息。
- 同进程耗时使用 `performance.now()`，时间轴另存墙钟。阶段累计工作量、重叠区间合并后的占用时长、扣除直接子区间的自身耗时分别显示。跨持久暂停的审批区间标明是持久时间戳计算；不宣称为单调计时。崩溃保留最后观察时间，终止时间未知。

GenAI 映射固定在上游提交 `e57c543b4889619eb2a05702471937db5119165d`，由适配层导出；升级映射与 SDK 版本需重新跑协议测试。[上游定义](https://github.com/open-telemetry/semantic-conventions-genai/tree/e57c543b4889619eb2a05702471937db5119165d/docs/gen-ai)。远端 MCP 内部不可见的过程不生成假节点。

## 原始 HTTP 材料

`adapters/observability/transport.ts` 使用 SDK 可注入 fetch 捕获实际字符串请求体和解压后的响应体。JSON 不重新序列化；SSE 按实际字节顺序写入，包括私有续接与加密字段。Authorization、Cookie 和其他请求头不进入存储。只读取响应状态码、Content-Type 与请求 ID 等白名单。

原始材料不等于可读聊天，不经过 8000 字符工具预览，也不自动脱敏正文。只通过独立本机接口、用户主动打开的页面读取；不送入普通历史、Agent 工具、聊天 SSE 或 OTLP。结构化显示是浏览器对原始文本的派生格式；下载保持原始字节。

文件位于数据目录 `observability/captures/`，目录 0700、文件 0600。每份默认 20 MiB，全库默认 1 GiB；每个写入器队列最多 20 MiB。队列满、容量满、磁盘错误或断流均保存前缀并标明 partial，不阻塞模型输出。索引记录大小、SHA-256、原因和 complete / partial / capturing / purged。

SDK 在 Chat Completions `[DONE]` 后可能提前关闭消费者。调试模式使用原始 Run 取消信号控制真实连接，并最多用 150ms 在后台收拢已有 HTTP 尾部：不发新请求、不等待磁盘、不阻塞业务返回；只有见到真实 EOF 才标完整。业务请求活动期间，用户取消立即取消真实连接。模型正常结束后释放请求级取消监听，避免 Loop 的 finally 清理被误判为用户停止；尾部仍受 150ms 上限约束。未见 EOF 保持缺损标记。

先写 `.part`，关闭与 fsync 后原子发布 `.raw`。重启对账已引用材料的实际字节与哈希；已完成文件发生变化时标记 `partial/integrity_mismatch`，未引用临时对象回收；不重新请求模型。总容量回收优先选已结束、不可恢复任务的最早材料；没有可回收对象时本次采集明确不足。Trace 和正文默认最多保留 30 天，清理不影响聊天及长期账本。

## 用量与费用

唯一记账单位是一次实际模型 HTTP 请求。排队取消不产生已发送调用；流式累计 usage 覆盖保存而不相加。失败、停止、重生成旧候选仍保留已取得的用量。主成员、摘要、后台记忆、连接测试按用途分类，汇总只统计叶子调用。后台记忆不按来源会话重复分摊。

金额使用十亿分之一货币单位的 BigInt 定点运算，最终以十进制字符串传输。缓存读取、写入与普通输入互斥；reasoning token 是输出子集，不重复计费。缺少 usage、缓存分类或适用价格条件时费用为 null，页面显示已知小计和未计价请求数。

内置价格核验日期为 2026-09-29。官方 OpenAI 普通端点支持已核实模型的缓存、272k 阶梯和 default / flex / fast / priority 档位；其他条件未知就不套价。DeepSeek 支持明确的非高峰时段，工作日高峰涉及节假日条件而未内置日历，保留未知。自定义代理只使用用户配置的连接/模型价格，不套用同名官方价。[OpenAI 价格](https://developers.openai.com/api/docs/pricing)、[长上下文档位](https://developers.openai.com/api/docs/models/gpt-6-sol)、[DeepSeek 价格](https://api-docs.deepseek.com/quick_start/pricing/)。

每次请求绑定当时的价格版本；调价不重算旧账。USD/CNY 分别汇总，不换汇，不等同于订阅扣款或服务商账单核销。删除会话在同一事务中转存不含会话/项目/Trace/调用身份的匿名日期-模型-用途汇总，再清除明细与材料引用，重复删除不重复累计。

## 故障边界

Trace 元数据用有界队列最长 250ms 合批，结束、暂停和关闭冲刷；诊断丢失只增加缺损计数。账本意图和 usage 独立立即持久化；写入失败封闭后续付费请求，不重发已发送请求。OTLP 默认关闭，仅发送元数据，有界内存队列、2 秒导出超时和最多 3 秒关闭等待，不建立持久外发队列。

原始材料保留只面向可信本机单用户；没有新增公网访问模式、远程正文导出、指标平台、日志平台或权限角色系统。

## 任务与执行段

Web 按 rootRunId 归组，一个任务一张卡；真实恢复产生的执行段仍可单独选择。卡片状态读取主 Run，不使用最后一个成员段推断任务成功或失败。终态提交（包括没有活动协程时取消审批）必须关闭句柄；迟到打点不能创建新运行。启动时对照真实 Run 修正旧悬挂段的状态，保留原 ID 和关联；结束时间未知的节点仍标记缺损。

累计产出与上下文窗口分别统计：模型输出、参数/续接与工具预览保留计数，但不再设置任务累计上限或总时限。MYAGENT_OUTPUT_CHARACTERS / MYAGENT_RUN_TIMEOUT_MS 已停用，旧快照字段也不再参与终止判断；上下文容量和单次调用超时独立生效。

## 任务视图与事实边界

观测 Step 从上下文准备前开始，包含一次 Agent 决策请求及其工具批次；摘要请求嵌套于 context.prepare/context.compact。前端通过独立展示投影组织任务、成员、Step 和工具批次，原始 Span 保持不变；并行条共用时间轴，分组显示观察跨度而非累计子节点耗时。正常检查收进详情，异常和显著等待仍突出。

节点详情是单页连续分区。已有业务 Step、工具回执和消息通过只读 evidence 端口注入；只选公开安全字段，不返回 StoredStep.continuation。选中模型节点才自动读已采原文，复制与下载保持原文。上下文来源差异只保存身份、哈希、类别和大小，不能将正文写进属性、日志或 OTLP。
