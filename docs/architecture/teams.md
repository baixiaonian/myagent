# 轻量多 Agent 协作

[工具、启动与通信展开](../../diagrams/agent-teams-tool-flow.svg) · [整体关系图](../../diagrams/agent-teams.svg) · [图源与源码映射](../../diagrams/README.md)

用户对话中的 Agent 负责整体交付，可以亲自执行，也可以创建成员。成员有独立历史和角色，共享项目，通过持久消息直接交流。所有参与者仍调用同一个 `runAgent`，没有规划专用模型或第二套循环。

## 一次任务如何运行

1. ChatService 创建主 Run，TeamService 保存团队范围、模型连接与统计关联。没有协作工具调用时仍是普通聊天，不额外调用模型。
2. 主 Agent 调用 `spawn_agent`。成员身份、内部会话、初始背景、请求消息和待启动意图与工具成功回执同事务保存，提交后维护器才启动成员。
3. 成员使用主 Run 的连接、协议、容量和项目规则/Hook/插件版本；Skill 根据自身任务选择。每个成员都通过 ChatService 使用原来的上下文和执行链路。
4. 成员可以 `send_message` 给主 Agent 或其他成员。空闲成员收到 request 启动工作；inform/result 只入箱，不自动唤醒空闲成员。活动成员在上批工具完整落库后、下次模型请求前读取。
5. 成员终态和完成回执同事务保存。主 Agent 提前给出最终文字但成员未完成时，这段文字只是候选；主 Run 保存检查点并进入 `waiting_agents`，收齐结果后继续模型决策。
6. 主 Agent 交付前再次事务核验待处理成员和消息。用户停止主 Run 会取消本轮成员；完成后成员空闲，下一条用户消息可复用同一身份。

## 实现位置与状态归属

| 位置 | 职责 |
| --- | --- |
| `contracts/teams.ts` | 成员/消息/分页 DTO、中立 RunCommandPort |
| `orchestration/index.ts` | FIFO 模型请求名额、等待环检测；不调用应用层 |
| `application/teams.ts` | 团队范围、收件箱、调度、收尾、分支、统计和共享范围 |
| `application/chat.ts` | 唯一 Run 生命周期，复用模型/上下文/工具/恢复链路 |
| `kernel/runtime` | 通用安全边界输入与完成确认回调，不认识角色或工具名 |
| `state/teams.ts`、`adapters/storage/sqlite/teams.ts` | durable 意图、消息、游标、检查点与共享事务 |
| `adapters/execution/team-tools.ts`、`application/tools.ts` | 六个协作工具的最终校验和调用记录；协调等待不占业务槽位 |
| `apps/server`、SDK、`TeamPanel.tsx` | 唯一装配、管理 API、成员过程和审批展示 |

## 上下文与权限

创建成员默认只共享任务与必要的原始用户约束，也可选择最近完整轮次或完整有效历史。完整历史仍受容量与摘要管理；不复制私有推理续接、审批或未完成工具批次。共享材料明确标为背景，成员消息不能冒充用户授权。成员消息保存 `origin`，避免请求被误认成直接用户指令。

角色在每次成员 Run 保留。成员之间默认只看到收件箱；`read_agent_history` 对主 Agent 开放成员过程，对成员限制为自身或显式共享内容。大型结果复用持久引用与分页，读取校验团队、分支、来源关系。成员可使用长期记忆，但不能直接修改记忆，也不独立贡献后台提炼。

成员复用父会话的资源授权上限，工作区身份、规则更新和撤销仍实时复核。一次性授权始终绑定实际成员调用，不能被复制给另一成员。命令审批仍由用户操作，主 Agent 无权代批。共享锁只保护一次工具操作，模型仍需分配文件责任、处理版本冲突并验证逻辑。

## 调度与恢复

默认每团队 8 个未关闭成员；全局模型并发 4，含主成员、上下文摘要、后台整理和连接测试。FIFO 等待可取消，不占业务工具槽位。工具保持每 Run 4、全局 8。团队累计产出和活动时间仅作统计，不设总输出配额或总时限；主任务与成员均通过各自上下文压缩持续推进。等待消息且其他成员正在工作仍统计活动时间；纯人工等待沿用暂停语义。单次模型/工具超时与并发边界独立保留。

消息先落库再确认；已入队、已纳入请求、已回复分别记录。收件箱游标与内核检查点同事务；完成确认检查点能防止恢复时凭空多调一次模型。等待环只提示冲突，不替模型决定分工。

重启暂停所有未结束范围，不自动产生模型费用。用户恢复主任务后继续原版本成员；审批、容量不足和未知副作用仍各自处理。重新生成创建独立候选团队，成功后切换；失败保留原团队。成员真实文件修改不会回滚，重新生成主问题也检查成员副作用。

会话删除先取消并收拢成员，再级联内部会话与派生记录，保留现有未知副作用最小隔离事实。关闭成员只释放名额，历史保留。

## 首版边界

仅本机 MyAgent；只有主 Agent 创建和停止其他成员。没有递归子团队、网络 A2A、角色模板、独立 worktree、共享任务板或固定工作流。结果汇总由模型负责，框架只保证生命周期与执行事实，不能将 succeeded 当作额外质量评价。

协议见 [v11](../protocols/teams-v11.md)，使用见 [维护说明](../development/teams.md)。
