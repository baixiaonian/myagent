# ADR-0006：对话选择项目与文件驱动 MCP 配置

- 日期：2026-09-15
- 状态：已采用
- 部分替代：ADR-0005 中独立添加工作区与手动连接的产品入口；执行治理约束继续有效。

## 问题

旧界面要求先创建工作区再绑定会话，打开 MCP 设置还会创建空会话。配置只有数据库入口，页面没有完整工具目录，持久化连接状态也不能证明重启后的真实连接。

## 决策

新对话直接选择原生目录；不选择时每会话独立默认目录，自动登记和原子绑定。目录与凭证/数据库分离，删除会话保留产物。

MCP 以用户级和项目级 mcp.json 为单一配置事实源，表单与文件编辑共用。项目级整体覆盖同名用户级，包括禁用；外部项目变更需确认准确版本。凭证独立保存，逻辑引用不跨服务和作用域继承。

配置文件与 SQLite 通过提交日志衔接，崩溃时按文件事实完成或放弃投影；不重放业务调用。连接、状态和工具目录按服务身份/版本/工作区隔离。无会话的设置页使用专用检测目录，禁止业务 tools/call。

继续使用现有 SDK、ModelPort、自主 Loop、ToolService 和原生 Worker。目录选择是可信用户管理 API，不是模型自由执行宿主程序的通道。

## 替代方案与后果

单一共享默认目录更简单，但不同对话容易相互修改文件；因此选择独立目录，并接受用户需要管理保留产物的成本。

只在数据库保存配置易实现，但无法自然支持外部编辑器；文件事实源增加并发、迁移和凭证转换工作，因此提供哈希版本与恢复日志。

全局共享 MCP 客户端节省进程，但不能准确隔离项目 cwd、目录和权限；选择项目实例隔离。不是每次界面轮询都重连，失败后由用户重连，避免无限启动失败进程。

浏览器上传目录不能代表后端的真实项目目录；本机采用系统窗口，容器/无桌面提供显式路径与浏览回退。Windows 和桌面应用壳不在当前范围。
