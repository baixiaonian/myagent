# ADR-0018：取消任务累计产出上限和总时限

日期：2026-09-29。状态：已采纳。替代 ADR-0015 中的团队累计额度约束。

## 问题

原实现对整个团队累计模型文字、参数、续接和工具预览设置 200000 字符上限，并设置 10 分钟活动时限。两者不因上下文压缩而减少，合法的长任务仍会触顶；维护任务随后通过停止接口取消主任务，无法完成交付。

## 决策

- 删除 Run、团队和摘要的累计字符配额及任务总截止时间，不改成更大的隐性常量。产出、活动时间和实际 token 继续统计。
- 每次请求由现有 ContextService 管理窗口、原文选择、完整批次摘要及历史查阅。模型仍自主决定继续、调用工具或结束，不新增强制轮数或收尾请求。
- 保留单次模型 120 秒、普通工具 30 秒及单命令进程默认 600 秒超时；命令默认使用独立 `commandTimeoutMs` / `MYAGENT_COMMAND_TIMEOUT_MS`。原始结果采集、工具预览、单份摘要和并发边界保持。
- 旧 `runTimeoutMs` / `outputCharacters`、团队 `timeLimit` / `outputLimit` 及对应环境变量忽略，恢复不能重新启用旧限制。SQLite 仍为 v13，无需改写历史。
- 不自动重跑已经失败或停止的任务，不抹去既有错误与副作用记录。停止、网络失败、单次超时、存储失败及未知副作用继续按真实状态处理。

## 取舍与后果

任务可跨过原来的累计阈值持续执行；上下文窗口控制的是单次模型输入，无法约束总费用或磁盘使用。首版按用户选择取消总量中断，不把窗口管理描述为无成本、无限存储或永不失败。保留可观测用量、用户停止、物理采集边界和持久恢复。

对“提高默认总配额”和“仅移除工具日志计数”两个替代方案不予采用：它们仍会在正常长任务中产生人为终点。当前模块依赖和唯一循环保持不变。
