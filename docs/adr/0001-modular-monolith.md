# ADR-0001：模块化单体与稳定内核

日期：2026-09-08。状态：采纳为目标架构，业务实现待开发。

问题：从零构建完整 Agent，需要模块可替换，同时控制系统维护与部署成本。

决策：后端由单一装配入口构造应用、内核、状态与适配器；执行环境可独立。内核不依赖具体框架、数据库或模型厂商。业务状态、观测事件与外部动作分别建模。

替代方案：直接 fork 一个上游完整产品、从第一天部署微服务、让每个能力都动态替换内核。当前自有产品目标更适合保留稳定边界、按需扩展。

后果：需自己维护核心协议与运行语义，但模型、存储、执行后端可局部替换。模块边界必须通过工程检查和未来契约测试持续验证。
