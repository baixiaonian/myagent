# ADR-0002：工作区与工程工具

日期：2026-09-08。状态：已落地工程骨架。

问题：目标目录需要可独立定位、可构建、可检查，且全新 AI 上下文应能快速接手。

决策：4 个应用和 11 个库作为 pnpm 工作区。kernel 的内部职责保持子目录。公共库为私有 ESM 包，使用 TypeScript 项目引用；types 指向源码便于干净工作区做类型解析，运行入口指向 dist，运行前需要 build。Web 使用 Vite 打包。

模块清单维护允许依赖；应用组合根声明装配所需包。当前仅建立工作区关联，不实现业务接口或虚假成功处理器。main.ts / main.tsx 是应用入口；空目录用 .gitkeep 保留。扩展目录不创建可被误加载的假 Skill 或插件。

工具选择：TypeScript 6.x + Biome + Vitest；业务基础设施依赖待真正使用时再增加。使用 tsc -b 同时进行项目图类型检查和增量编译，因此 typecheck 会生成缓存与编译产物。

知识管理：根 / 局部 AGENTS.md 管开发规则，STATUS 管当前事实，architecture / protocols 管有效设计，history 追加迭代记录。文档检查验证链接、必要文件及模块索引，语义一致性仍需开发者审查。

替代方案：全部放单包（弱化依赖边界）、每个子目录拆包（管理成本过高）、预先安装完整目标栈（增加未使用依赖）。

后果：新增包时需要同步清单、project references、模块表和文档；已有目录内新增功能成本较低。CI 用 frozen lockfile 与 pnpm verify 验证工程。
