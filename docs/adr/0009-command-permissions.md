# ADR-0009：命令启动权限叠加资源隔离

日期：2026-09-22。状态：已采纳。补充 [ADR-0005](0005-controlled-tool-execution.md)，不改变单一自主 Loop。

## 问题与选择

工作区允许读写不等于任意命令都应自动执行。新增命令启动检查，将默认明确低风险自动执行、显式规则与一次审批接入现有 ToolService；资源策略和 OS 沙箱继续独立约束真实执行。

Shell 解析使用适配层的 Tree-sitter WASM，不用正则猜测完整 Shell 语义，不引入额外模型裁判。内核只持有端口和纯规则组合。Bash 语法树用于保守识别静态子集，实际仍使用既有非登录 `/bin/sh`；复杂或不确定语法进入审批，不宣称两者完整语义等价。

用户和项目规则组合采用 deny > prompt > allow，同名项目规则不能放宽用户限制。文件是事实源，设置表单和 JSON 编辑器共用版本保护；外部项目变更由人确认准确版本，不能由模型写文件自行授权。

命令批准只对一次调用有效，不扩展为整个会话/工作区。长期放行通过可审查规则配置。审批绑定完整命令和实际目录，而非只批准某个前缀。

## 明确边界与替代方案

已确认仅检查 `exec_command`，不逐次审批 `write_stdin`；批准交互式 Shell/解释器表示信任该实例后续输入。内部子进程不逐次拦截。相比全进程树拦截，当前方案保持执行环境简单并复用现有沙箱，但规则不能证明程序内部行为安全。

没有选择模型风险打分、按字符串开头放行、默认放行全部工作区命令、项目规则覆盖用户 deny 或一次弹窗永久放行。命令数量和计划是否完成仍由模型决定，Loop 无新增决策分支。

## 后果与验证

模糊命令会比以前更多地询问；Git 默认询问，因为所谓读取子命令仍可能触发外部助手。默认读取名单、固定可执行文件来源和参数组合有对应测试，用户通过显式规则减少重复确认。

SQLite 升到 v5，阻止旧程序绕过新增检查。源码、接口、恢复细节见 [命令权限协议](../protocols/commands-v5.md)，用户操作见 [使用说明](../development/commands.md)。
