# ADR-0008：同会话复用有效的 MCP 按需工具定义

- 日期：2026-09-22
- 状态：已采纳；扩展 ADR 0007 的按需复用范围。

## 问题

按需目录只存在 Run 检查点中，下一次用户提问从空列表开始。模型需重复搜索已经发现的工具，既增加请求，也让多轮使用体验不连贯。按名称无条件复用又会接受变更后的工具，或误用其他会话的项目配置。

## 选择

应用层 McpToolSelection 管理会话选择缓存，新 Run 继承仍有效的版本引用；完整定义仍来自当前注册表，每次请求校验。引用绑定会话、目录身份、连接身份/版本及工具定义版本。临时断连保留引用但不提供工具；重新握手、发现且版本相同才恢复。新 Schema 必须重新搜索。

缓存与 Run 检查点同事务保存；先写检查点验证运行仍活动。删除会话级联清理。任务后续失败/停止不撤回已经提交的发现事实；缓存与执行许可分开，批准一次不能变成后续永久授权。旧检查点没有版本绑定时从空选择开始，不迁移猜测事实。

继续使用每次搜索 5 个、按需定义累计 16,000 字符的边界，按最近搜索选择排序淘汰，重复选择移到末尾。direct 独立提供且只计入整体上下文预算。不改变 Kernel Loop、模型端口或授权执行流程，不新增依赖或公开 API。

## 替代方案与后果

- 不使用进程级 Map 作为持久事实：应用重启和多会话不能可靠恢复/隔离。
- 不保存完整 Schema 作为可调用目录：会遮蔽断连和定义更新，形成第二个目录来源。
- 不从全部 Run 历史反向拼接选择：淘汰项会复活，也无法可靠验证旧定义版本。
- 请求仍需要发送工具定义。本改动减少重复搜索及相应模型调用，不宣称消除上下文成本。
- 注册表尚未发现的工具暂不可见；缓存不主动重连，也不重放任何业务工具调用。
