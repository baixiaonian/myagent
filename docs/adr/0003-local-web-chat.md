# ADR-0003：本地单用户 Web 聊天闭环

日期：2026-09-08；状态：已采纳；衔接 ADR-0001 / 0002。

## 问题与选择

在完整 Agent 骨架内先交付可独立使用的文字聊天。采用 React/Vite + Fastify 单进程装配；生产同源托管，开发代理。保持 contracts / SDK / application / kernel / state / adapters 边界，不在 Web 中直接调用模型。

SQLite WAL + better-sqlite3 同步短事务便于将消息、Run、事件一并提交；Drizzle 提供类型化查询，版本化 SQL 迁移保存于 migrations。选择单实例数据目录锁和每会话 running 唯一索引，而不是引入分布式队列。250ms 合并写入控制写放大，SQLite 事件日志支持无外部 broker 的 SSE 重放。

使用官方 OpenAI TypeScript SDK 的最小 Chat Completions 流式请求，maxRetries=0。不预取模型列表，不发送工具或额外参数，避免将单厂商扩展当作通用协议；使用本地 HTTP 兼容服务验收分片、取消、错误和缺少 usage。

凭证与 SQLite 分离，引用经 UUID 间接关联，原子更换文件，目录 / 文件权限限制本机其他用户。没有加密或系统钥匙串集成；本机账户本身必须可信。两份存储不能跨文件事务，更新采用“先持久新密钥，再提交配置，再清理旧密钥”，异常退出可能留下无引用凭证，不会让已提交配置指向尚未写入的新凭证。

候选答案与原答案分开；重新生成成功后原子标记旧答案 superseded。历史保留旧版本用于调试，界面只投影有效版本。不自动重试模型、不自动恢复中断 Run，控制重复计费风险。

## 替代方案与后果

PostgreSQL、Redis、Worker 队列适合多用户扩展，会增加当前安装成本，因此保留未来替换条件。凭证放浏览器或数据库更简单，但违反本轮凭证隔离目标。纯前端直连会泄漏密钥并丢失后端持久运行，不采用。Response API 不作为本轮兼容基线，后续可新增 ModelPort 适配器。

仅支持单机可信用户。容器只向宿主 loopback 映射端口，Host/Origin 检查是浏览器访问防护，不等于公网身份认证。若未来需要多租户，必须另行设计认证、配额、隔离与部署。
