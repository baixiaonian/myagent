# 工作台深度审查与交互优化

## 目的与参考边界

根据用户指出的对话过程、审批、子 Agent、上下文占比和 Skill/MCP 使用问题，审查并修改现有 Web 产品。沿用现有公开 SDK、执行策略、会话与草稿规则。

本轮实际查看本机 Qoder：整轮工具折叠、右侧任务监控、输入框下的窗口百分比。只读查看本机 deepseek-harness 的 `ContextMeter`、`ApprovalPanel`、`ToolCallTree`：小型占用仪表点击展开，审批长正文与按钮分离。dsh 未启动实机界面，源码参考不代表运行验收。Codex 桌面访问被工具安全限制拒绝；参考其官方公开[交互资料](https://developers.openai.com/blog/mastering-codex-remote-for-engineering)，未声称读取私有 UI 或验证其全部桌面交互。

## 审查发现与处理

1. **新对话与侧栏**：原设置入口逐行占用大量会话空间；输入区的项目与权限分散成多行。设置入口压为紧凑网格，输入区统一控制行，保持项目归组、独立目录、IME、会话草稿和主动上滚行为。
2. **已完成对话**：原 36 次工具调用仍留下数十行批次，难以重新读最终结果。现在按一轮聚合，执行中默认展开、进入终态自动收起一次；手动展开后不会被轮询收回。最终答案保持独立，异常计数常驻，工具参数、结果与中间说明全部保留。
3. **审批**：原卡片与聊天同滚动，授权范围与命令细节不易辨认。现在紧邻输入区，命令、目录、范围和主要按钮分层；长正文可独立滚动，按钮始终在卡片底部。各审批按 ID 保存范围，避免上一张的长期授权选项泄漏到另一张。命令仍只能批准一次。
4. **成员**：原团队在主消息尾部铺开，挤占正文。现在在右侧独立滚动，显示任务、状态、用量、过程及控制入口；收起侧栏不停止成员，不丢主输入草稿。窄屏以可关闭侧栏覆盖显示，成员内部审批和恢复继续复用既有组件。
5. **上下文**：原只显示 token 比值，而且分母是输入预算。现在常驻显示完整窗口占比，点击显示估算值、完整窗口、可用输入预算、来源分类、摘要和原文；Escape/外部点击关闭。未知数据不冒充零。比例来自当前 Run 冻结容量，不能用刚修改的模型设置重算旧任务。
6. **技能**：原空态添加入口藏在来源目录中，搜索无结果与无技能混淆，详情落在长列表末尾。现在有直接添加入口、启用统计、明确搜索空态，以及列表/详情布局。保留只读正文、作用域、版本、来源与按轮选择；选择菜单支持外部点击、Escape 和输入法。
7. **MCP / 其他设置**：原配置文件路径抢占服务列表，页面之间必须关掉再打开。现在使用统一设置导航、服务连接数、名称/工具搜索、状态及工具数量；配置文件折叠但待确认/错误自动展开。主要设置表单切页前保护未保存输入；轮询不覆盖草稿。连接状态继续使用服务端事实，不把启用当作连接成功。

## 实现与协议

- Web：`workspace.css` 定义新工作台展示层，`SettingsNavigation` 提供统一导航；`Modal` 处理导航与草稿提示，业务状态仍由原设置组件拥有。
- `RunProcess`、`TeamPanel`、`ExecutionPanel`、`ContextPanel`、`SkillPicker` 与技能/MCP 设置更新；不新增 Agent 循环、不改工具权限。
- `ContextView.capacity` 是兼容可选字段，读接口投影已有检查点中的 `contextWindowTokens/outputReserveTokens`。旧服务不提供时显示待估算，不用输入预算冒充完整窗口。无数据库迁移，无 SSE 版本变更。
- 已检查根、apps、apps/web、packages/application、tests、docs AGENTS；更新 Web 交互约束。模块职责与依赖边不变，`config/modules.json` 无需修改。
