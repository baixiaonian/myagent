# 2026-09-26：工作台界面与项目重新选择

## 原因与实现

本机两个最近项目的规范路径和 inode 未变化，当前 dev 为 16777231，而已有 identity 对应 dev 16777229。现有身份校验拒绝旧目录记录，但新对话 prepare 也一律拒绝，导致用户重新选择无路可走。

ProjectService 现在只复用同路径同身份记录；用户显式选择新身份目录时登记新 workspace ID。旧会话、授权和 MCP 信任不迁移，执行层 LocalWorkspace.validate 不变。最近项目按规范路径显示最新登记。新增测试验证新对话可以绑定、重复选择复用新身份、旧记录/授权仍保留、旧身份执行仍被拒绝。

Web 改为中性浅色紧凑工作台：项目与对话侧栏、桌面收起/展开、新对话欢迎区、输入区模型入口。项目选择使用可搜索非模态菜单，最近目录/默认目录/原生选择为主要操作，手动路径和浏览作为次级对话框。关闭、取消或错误不清空草稿；异步选择在组件卸载后不会写回。

## 参考与边界

Computer Use 明确禁止读取 Codex 客户端自身，未绕过限制、未取得客户端私有源码。本轮依据用户给定的输入区截图及 OpenAI [公开界面](https://developers.openai.com/blog/run-long-horizon-tasks-with-codex) 调整布局与交互；这是 MyAgent 已有功能的适配，不宣称与用户当前 Codex 版本逐像素一致。品牌和功能文案保持 MyAgent，未增加空的自动化/插件/附件入口。
