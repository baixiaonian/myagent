# 2026-09-29：Trace 生命周期与任务归组修复

## 现场与原因

用户本机一次文档整理任务创建 4 名成员，共 28 次真实模型请求，全部正常完成。对应 28 条 Trace：23 个 waiting_approval、4 个残留 running、1 个 failed；同会话更早的问候不计入此任务。证据 `.cache/trace-case-before.json` 仅含身份、状态与计数，不含项目正文、私有续接或凭证。

Trace 碎片来自审批暂停退出 ChatService.launch 时立即 endRun；主句柄被移除后，成员不能继续挂到它下面。取消一个没有活动协程的暂停 Run 不经过 launch.finally，审批收尾打点新建的 Trace 没有终结。因此旧 UI 的 running 并不代表仍在调用模型。

失败另有原因：一个成员达到共享输出上限，团队累计 201079 / 200000 字符，工具回执模型预览约 16.6 万字符。主任务终态记录为 cancelled。输出上限包含模型输出、参数/续接和工具预览，与 200k token 上下文窗口是不同约束；没有证据表明是模型网络请求失败。28 次命令审批中 24 次批准、4 次取消；部分命令含 echo、Git 或复杂组合，按现有保守命令策略需审批。

## 修改

- 同进程审批/团队等待保留 Trace，以等待 Span 表示；重新进入循环结束等待 Span，成员保持同一主链路。真正持久暂停及重启仍建立 Link。
- 业务终态提交即通知观测，覆盖暂停时取消；真实终态阻止迟到打点新建 Trace。
- 启动对照 Run 修正遗留 running 段，保留原 ID、原始材料及用量账本。未知节点结束时间不补造。
- Trace DTO 增加可选 task 状态投影；页面按主任务归组，旧执行段可切换查阅。成员错误从实际 Run 投影，空闲状态不掩盖失败。
- 配额错误显示已用量、上限和字符单位。本轮没有放宽命令策略、改变输出上限、重跑用户任务或自动调用模型。

- 本机服务已在原 3000 端口更新。重启前完整备份数据至受保护数据目录的 backups，位置记录 `.cache/trace-fix-local-backup.json`。重启后原任务仍为 cancelled、实际调用数仍为 28；原始 28 个 Trace ID 保留，4 个残留 running 校正为 cancelled，页面归组 1 个任务；证据 `.cache/trace-case-after.json`。
