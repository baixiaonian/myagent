# 2026-09-08：拆分提交历史与中文提交规范

## 目的与范围

用户要求把初始化和聊天机器人开发拆成两个提交，并用中文说明完成的工作。原始 main 只有聚合根提交 `7424b556bbf95a249f9c7cc363dc16423655e21f`，将两个开发阶段同时纳入了首次 GitHub 基线。本轮按用户授权重组已推送历史，新增提交规范；产品运行逻辑和数据格式不变。

## 两个提交的边界

1. `chore(工程): 初始化模块化工程骨架与项目知识库`：保留架构研究交付物；创建 15 个 workspace、占位入口、工具链、依赖边界检查、8 项工程测试、AGENTS 和初始项目知识。业务包公开入口仍为空模块，无聊天、模型通信、HTTP API 或数据库实现。
2. `feat(聊天): 实现本地 Web 聊天机器人并完成测试与交付配置`：在骨架上实现聊天所需的 8 个模块，加入设置、会话、流式运行、持久化、可靠性与凭证边界，补齐测试、Docker、启动脚本和知识文档；同时建立中文提交规范。完整 Agent 的其余模块继续标为骨架。

第一阶段依据初始化时保留的文件生成及修正记录，在隔离目录恢复，使用当时固定的直接依赖版本重新生成锁文件并验证；不是从聊天成品中任意删文件凑出的占位提交。两个 Git 提交均在本轮实际创建，不伪造过去的提交时间。原先各轮历史文档保留，代表实际开发过程；Git 边界是本轮整理结果。

根 AGENTS 新增 Git 提交规则，详细规范位于 [commits.md](../development/commits.md)，知识地图和工作流补充入口。要求 `type(scope): 中文完成项摘要`、一个可验证工作单元一个提交、实现与必要测试和知识同步提交，并记录真实验证及限制。当前采用约定与人工检查，未引入 hooks 或新依赖。

更新 STATUS 和历史索引；检查 docs/AGENTS.md，现有局部规则适用，无需空改。模块职责、依赖与协议均未变化，因此不新增 ADR 或迁移。
